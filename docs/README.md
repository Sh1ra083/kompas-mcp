# KOMPAS MCP

Лицензия исходников — [MIT](../LICENSE).

Локальный MCP-сервер для автоматизации установленного КОМПАС-3D через Python и COM. Позволяет создавать детали, сборки и чертежи, выполнять сохранённые сценарии и проверять геометрию.

**Текущая версия — `0.4.0.dev1`, предварительная разработка.** Машиностроительные адаптеры проверялись на КОМПАС-3D v25 Educational x64. Строительные инструменты экспериментальные: нормативный каталог пока содержит метаданные документов, **проверенных нормативных правил — 0**. Полное выполнение первоначального плана не заявляется.

## Возможности

- Документы и рабочие копии с зависимостями, контрольные копии, сохранение и экспорт.
- Эскизы, типизированные операции деталей, поверхностей и листового металла; параметры и геометрический поиск.
- Компоненты, размещение, сопряжения, диагностика сборок.
- Виды, размеры, разрезы, спецификации и проверка расположения на листе. Проекционные связи сохраняются.
- Пакетные сценарии с зависимыми шагами и компактными ответами.
- Экспериментальные строительные проекты: стены, проёмы, помещения, мебель, площади, столкновения, предварительные M3D/CDW из AEC-шаблона.

Указание инструмента в API не означает приёмку всех его режимов. См. [статус машиностроения](COMPATIBILITY.md) и [статус строительной части](BUILDING_STATUS.md).

## Требования

- Windows x64, Python **3.12 x64**.
- Установленный КОМПАС-3D с зарегистрированным COM API. Проверенная локальная среда — v25; другие версии и редакции требуют испытаний.
- Для строительного предпросмотра — доступный `AEC.cdt`. Путь задаётся через `KOMPAS_MCP_AEC_TEMPLATE`; если переменная отсутствует, адаптер пока использует `D:\KOMPAS\Bin\Resources\docTemplates\defaultTemplates\AEC.cdt`.

COM исполняется непосредственно в Windows. КОМПАС, его SDK, библиотеки типов, шаблоны, учебные PDF, сторонние бинарные серверы и их активация в репозиторий не включены.

## Запуск из исходников

В PowerShell из корня клонированного репозитория:

```powershell
./setup.ps1
```

Скрипт создаёт `.venv`, устанавливает зависимости из `requirements.lock.txt` и пакет. Сервер запускается MCP-клиентом через `.venv/Scripts/python.exe` с аргументом `run.py`. Это процесс stdio: stdout предназначен только для MCP.

Пример конфигурации клиента:

```json
{
  "mcpServers": {
    "kompas-local": {
      "command": "C:/CAD/kompas-mcp/.venv/Scripts/python.exe",
      "args": ["C:/CAD/kompas-mcp/run.py"],
      "env": {"KOMPAS_MCP_WORKSPACE": "C:/CAD/kompas-workspace"}
    }
  }
}
```

Замените примерные пути на абсолютные пути своей установки. Выберите отдельную папку результатов. Тайм-аут вызовов клиента должен превышать тайм-аут CAD worker, равный 120 с; рекомендуемое значение в примере — 150 с. Примеры находятся в [configs](../configs/).

## Сборка Windows-пакета

```powershell
./build.ps1
```

Результат — wheel и `dist/kompas-mcp/kompas-mcp.exe`. Для переноса нужна **вся папка** `dist/kompas-mcp`, включая `_internal`. `launch.cmd` запускает сборку, а при её отсутствии — локальное окружение. Фиксация версий не является гарантией побитово одинаковых EXE. Текущая версия остаётся предварительной разработкой.

## Рабочий маршрут

1. `connect` → `capabilities`: проверить установленную среду и доступные возможности.
2. `document_create` либо `document_open_copy`: работать с собственным документом или копией.
3. Создать эскизы/операции или запустить декларативный сценарий.
4. Выполнить `model_check`, проверить размеры, геометрию и ошибки дерева.
5. Сохранить, повторно открыть, проверить и экспортировать результат.

Единицы — мм и градусы. Ссылки на топологию действуют в текущем сеансе и ревизии; после изменения геометрию выбирают заново. При `timeout_unknown_outcome` изменяющую операцию не повторяют: сначала получают результат через `operation_status`. Завершение сервера не вызывает завершение пользовательского КОМПАСа.

Маршрут от изображения до модели описан в [WORKFLOW.md](WORKFLOW.md). Сценарии — в [examples](../examples/), схемы API — в [schemas.json](../src/kompas_mcp/schemas.json). Переносимость ссылок сложных сборок и PDM-проектов требует отдельной проверки.

## Строительные инструменты

`building_project_save`, `building_project_check`, `building_furniture_catalog`, `building_preview` и `norm_search` работают с отдельным JSON-проектом. Размеры мебели — редактируемые примеры габаритов, зоны использования задаются отдельно. Предварительный план пока не содержит полного строительного оформления и связанных разрезов/фасадов.

При неоднозначном запросе о расстоянии между перегородками справочник возвращает недостающий контекст. Карточки с `metadata_only` нельзя использовать как подтверждённые численные требования. Дата метаданных имеющегося набора — **15.09.2026**; публикация кода не обновляет эту дату.

## Проверки

```powershell
./.venv/Scripts/python.exe -m pytest tests -q
./.venv/Scripts/python.exe scripts/export_schemas.py
./.venv/Scripts/python.exe scripts/publication_check.py
```

Обычный CI не требует КОМПАСа. Нативные испытания запускаются отдельно на Windows с установленным CAD, в новой выходной папке:

```powershell
$env:KOMPAS_INTEGRATION='1'
./.venv/Scripts/python.exe -m pytest tests/test_protocol.py -q
./.venv/Scripts/python.exe tests/integration/acceptance.py --output C:/CAD/acceptance-new
./.venv/Scripts/python.exe tests/integration/building_acceptance.py C:/CAD/building-test-new
```

Строительная проверка сейчас использует простой однокомнатный технический пример. Это не полная приёмка пятизонного офисного блока. Все общие интеграционные проверки находятся в [tests/integration](../tests/integration/); они отделены от скриптов обслуживания.

## Скрипты обслуживания

В `scripts/` находятся только общие вспомогательные инструменты:

- `export_schemas.py` — обновление схем MCP для сборки и CI.
- `configure_clients.py` — создание конфигураций подключения к собранному серверу.
- `prepare_drawing.py` — подготовка и кэширование страниц PDF/изображений; требует дополнительных pypdfium2 и Pillow.
- `publication_check.py` — проверка подготовленных к коммиту файлов в CI.

Для запуска самого MCP эти скрипты отдельно выполнять не нужно. Учебные сценарии и материалы конкретных практических работ исключены из репозитория. В [examples](../examples/) оставлен минимальный универсальный сценарий пластины.
