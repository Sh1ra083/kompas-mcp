# Участие в разработке

Для разработки нужны Windows x64 и Python 3.12 x64. Установите окружение через `setup.ps1`. КОМПАС нужен для нативных интеграционных тестов; обычные unit-тесты не строят CAD-документы.

Перед pull request:

```powershell
./.venv/Scripts/python.exe -m pytest tests -q
./.venv/Scripts/python.exe scripts/export_schemas.py
git diff -- src/kompas_mcp/schemas.json
./.venv/Scripts/python.exe scripts/publication_check.py
```

После изменения публичных инструментов включайте обновлённые schemas.json в PR. Для изменения геометрии нужна проверка ожидаемых размеров/свойств, а не только COM-статуса. Для COM-операций сохраняйте STA-владение объектами и последовательную очередь. Не добавляйте автоматические повторы изменяющих вызовов после тайм-аута.

В описании PR укажите проблему, результат, проверенную среду и ограничения. Не помечайте нативную проверку пройденной, если она не выполнялась в установленном КОМПАСе. Сценарии запускайте в новой рабочей папке, закрывайте только собственные временные документы.

Нормативные карточки допускаются как verified только с проверенным полным текстом, применимыми изменениями, пунктом, источником, условиями и датами действия. Поисковый фрагмент и карточка документа для этого недостаточны.

В публичные issue/PR нельзя помещать секреты, исходные закрытые чертежи, журналы с личными путями или файлы SDK. Используйте небольшой пример, на распространение которого у вас есть право.
