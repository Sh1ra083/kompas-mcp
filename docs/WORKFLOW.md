# От чертежа до проверенной модели

Рабочий маршрут: **выбранные изображения → brief.json → сохранённый сценарий → один MCP-вызов → модель и короткий результат**.

1. Для PDF запустить `scripts/prepare_drawing.py source.pdf --output cache --pages 23`. Без `--pages` возвращается только число страниц. Изображения кэшируются по SHA-256 исходника и масштабу; повторная подготовка не рендерит их заново. Скрипт требует pypdfium2 и Pillow; они не нужны самому MCP-серверу. Для растрового чертежа передать изображение вместо PDF.
2. Один раз прочитать нужные виды. В `brief.json` сохранить источник/страницы, единицы, оси, размеры, взаимосвязи размеров, явные допущения, порядок операций и ожидаемые проверки. Нечитаемый размер не превращать в точное число. Этот этап выполняет помощник по изображению: универсального автоматического распознавания чертежей здесь нет.
3. Подобрать существующий рецепт или составить декларативный сценарий. Повторяющиеся отверстия объединять в один эскиз либо нативный массив; тело вращения строить одним профилем. Зависимые размеры вычислять в генераторе из одного набора параметров. Использовать геометрические признаки, не номера граней. Для резьбы получать шаг и диаметр основания из установленного каталога, затем выбирать цилиндр однозначно.
4. Сохранить сценарий в рабочую папку сервера. Значения `$params.name` заменяются целиком на параметры вызова; выражения Python не исполняются. Ссылки `$step.reference` связывают шаги, ссылки вперёд и неизвестные имена отклоняются до построения. `$params` можно использовать в любых значениях, но вычислений и частичной подстановки строк этот механизм не делает.
5. В конце сценария включить `model_check`, экспорт STEP, предпросмотр, окончательное сохранение, открытие рабочей копии и повторный `model_check`. После предпросмотра сохранить ещё раз: изменение ракурса может пометить документ изменённым. Для резьбы после открытия читать `thread_list`; для чертежа — `drawing_inspect`. Проверки должны покрывать важные размеры и отверстия, а не только число тел. Независимая проверка STEP и визуальное сравнение видов остаются отдельными необходимыми проверками нового рецепта.
6. Выставить `close_created: true`, выбрать короткие `outputs`: пути, SHA-256, успешность проверок, габариты. Вызвать `scenario_run_file(path, parameters)`. Он возвращает компактный ответ; весь сценарий, результаты шагов и контрольные копии доступны через JSON-файл и MCP resource из `report`. При обычном `scenario_run` прежний полный ответ сохранён; компактный режим включается `response_detail: "compact"`.
7. Читать полный отчёт только при ошибке или необходимости аудита. При изменении размеров менять параметры/генератор, не перечитывать весь PDF и SDK. Повторять геометрические проверки после каждого изменения. Не повторять тайм-аут изменяющего вызова: сначала `operation_status` и выяснение состояния.

Контрольная копия создаётся один раз для каждого документа, затронутого аргументами сценария. Чужие открытые документы не закрываются. Автоматически закрываются только созданные этим запуском сохранённые документы; несохранённые перечисляются в `kept_unsaved_documents`. После ошибки зависимые шаги не исполняются, частичные документы сохраняются в сеансе для диагностики, `restored: false` явно сообщает об отсутствии отката. Закрывать их после разбора результата.

Пример короткого повторного вызова:

```json
{"path":"support.recipe.json","parameters":{"name":"Опора фланцевая"}}
```


## Размещение и масштаб (0.2.1)
Перед выдачей вызывать `drawing_layout_check`: он получает свободное поле из оформления КОМПАСа и измеряет все объекты видимых видов, включая текст и размеры, в миллиметрах листа. Запас по краям и между габаритами видов — 3 мм по умолчанию. Системная точка начала координат исключается. Неизмеренные объекты не считаются прошедшими проверку.

`drawing_fit` сначала пробует перенос без смены масштаба. Виды с текстом/размерами по умолчанию не уменьшаются: нужен больший лист или перестановка оформления. Явное `allow_annotation_scaling=true` разрешает уменьшение, но требует визуального просмотра и, возможно, раздвижения подписей. После каждого изменения фактические габариты измеряются заново — размерный текст не считается пропорционально уменьшенным. Значения размеров не изменяются.

Контроль ограничен одним листом. Пересечения прямоугольных габаритов видов определяются консервативно; столкновения надписей внутри одного вида пока не распознаются автоматически. `passed` означает проверку размещения, а не готовность оформления без визуальной проверки. При невозможности размещения восстанавливаются исходные позиции и масштабы. Автоматическое создание большего формата не выполняется. Итоговые открытые документы пользователя при испытаниях не закрывать.

## Полное проецирование сборок

Стандартные виды и разрезы создаются с `IAssociationView.UseOcclusion=False`. Черновое проецирование может пропустить полностью закрытые детали даже в разрезе: это может скрыть внутренние детали сборки. После переключения обязательны Update/Rebuild и проверка `draft_projection=false`. Результат дополнительно сравнивается с составом сборки визуально; число объектов само по себе не доказывает полноту произвольной геометрии.
